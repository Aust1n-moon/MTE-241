=== QUESTION 1 ===
In your own words, explain what the HAL is and why it is used in a general embedded project.

The HAL, hardware abstraction layer, allows the users to access hardware using functions that are stored in the HAL header file. It makes it easier to read and write memory addresses and control peripherals like UART and GPIO, as you just need to call the HAL_UART_Transmit() function to handle UART transmissions internally, without having to manually deal with memory addresses. Since it is much easier to rely on the HAL library to access the hardware overall compared to writing setup code manually which is difficult, it is used in general embedded projects.

=== QUESTION 2 ===
In your own words, explain what the __io_putchar function does and why it is needed.

__io_putchar function is what the printf relies on in order to be able to output a character. It is responsible for writing a single character to the connected IO channel. Therefore, in this lab, by calling HAL_UART_Transmit, the character was sent over to UART2. This has to be written separately for every embedded project as each project uses different hardware and different IO channels to communicate, and there is not a universal way to write this over all STM boards.

=== QUESTION 4 ===
Explain how the stack allocation method we used works. Start by assuming that we have obtained the value for MSP_init_val. How did we get a new value for PSP_val? Why did we need to know the initial location of MSP for this to work?

The PSP_val was calculated by subtracting 0x400 from the MSP_INIT_VAL, where 0x400 is the size of the main stack. The location of the MSP value was needed to be found as that is the only reference point where the allocated stack memory begins. Knowing MSP_INIT_VAL allows the PSP_val calculation to fall within the memory that was reserved for the stack use, and not overlapping other data.

=== QUESTION 5 ===
Say that we wanted to use the same stack allocation method to allocate a number of new stacks for use in multiple threads. Say this number is known at compile-time. What would we need to change in our code to make this work?

To generate new stacks for multiple threads use, the formula ADDR_STACK_j = MSP_INIT_VAL - MAIN_STACK_SIZE - (j-1) * THREAD_STACK_SIZE is used, looping from j to 1 away from the known number of threads to compute each threads starting address. Each loop will subract the an additional THREAD_STACK_SIZE from MSP_INIT_VAL to prevent memory overlap, and all these total thread stacks combined, must fit inside the MAIN_STACK_SIZE so the memory does not overlap the others that may be used for something else.
